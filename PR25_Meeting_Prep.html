12. Likely Questions & Answers

Q: "Will this break existing pipelines?"
A: No. All new features default to enabled: false. The only config change affecting existing setups is partition.method → partition.algorithm (clustering).
Q: "Why 60 new packages?"
A: Pathway analysis (clusterProfiler ecosystem), annotation (biomaRt, AnnotationDbi), and interactive reporting (DT, plotly) each bring dependency trees. All versions are pinned in renv.lock.
Q: "Is the AI commentary sending our data externally?"
A: Only figure images (PNGs) are sent to Claude/OpenAI APIs when explicitly enabled with an API key. No raw expression data, sample metadata, or gene lists are sent. Fully optional.
Q: "Why ComBat-Seq as default batch correction?"
A: It operates on raw counts (preserves count nature for DESeq2), uses a negative binomial model, and is the most validated method for RNA-seq batch correction.
Q: "Why is deconvolution limited to human/mouse?"
A: xCell2 reference signatures only exist for these organisms. Other organisms get a clean skip rather than unreliable results.
Q: "How does organism auto-detection work?"
A: Regex pattern matching on gene IDs: ENSG→human, ENSMUSG→mouse, WBGene→worm, etc. Returns confidence level (high/medium/low) so the pipeline can decide.
Q: "What if the STRING API is down or unavailable?"
A: The PPI module first tries the STRINGdb R package, then falls back to the STRING REST API. If both fail, the module returns NULL and the pipeline continues.
Q: "How do we test this?"
A: Test plan from PR: (1) Run existing proteomics config with no new features — verify no regressions. (2) Enable pathway enrichment, verify output. (3) Enable AI commentary with API key — verify fallback without key. (4) RNA-seq end-to-end with batch correction enabled.
