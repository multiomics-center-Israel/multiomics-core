## 1. What this project does

`multiomics-core` is a `{targets}`-based **R bioinformatics pipeline** that runs standardised single-omics and multi-omics analyses:

- **RNA-seq** — DESeq2 differential expression, batch correction (ComBat-Seq/SVA/RUV), cell-type deconvolution (xCell2), pathway enrichment.
- **Proteomics** — limma-based DE with multi-imputation and stability filtering, PPI networks, advanced stats.
- **Metabolomics** — missingness classification, MNAR/MAR imputation, TSS/Median/PQN normalization, LOESS drift correction, DE (limma/t-test/Wilcoxon), pathway enrichment (QEA, ssGSEA, ORA, GSEA).
- **Multi-omics integration** — DIABLO, MOFA, SNF, concordance, cross-omics enrichment, WGCNA, COSMOS, consensus and stability analysis.

Behaviour is driven by a single **YAML config** (path passed via `MULTIOMICS_CONFIG`). Each run writes results under `<project.dir>/<paths.out>/Results_<project.name>_<analysis_round>/<mode>/`. AI-generated figure commentary is optional (Claude CLI / Anthropic API / OpenAI backends).

`README.md` (319 lines) is the user-facing entry point — read it for runtime details (setup, `renv::restore()`, running with `tar_make()`, organism detection, AI commentary setup).

## 3. The `R/` source tree

This is the heart of the codebase. It uses a **strict 5-layer architecture** that `_targets.R` enforces by sourcing files in this order:

```
R/
├── core/        Layer 1 — generic utilities, no domain knowledge
├── services/    Layer 2 — external integrations (AI commentary)
├── domain/      Layer 3 — omics-specific business logic
├── modules/     Layer 4 — target-ready wrappers around domain logic
└── pipeline/    Layer 5 — {targets} orchestration (sourced LAST)
```

**Files in each subfolder are numbered (`00_`, `01_`, …) to enforce load order within the layer.** When adding a new file, pick a number that fits the dependency chain.

### `R/core/` — generic utilities

Numeric prefixes encode dependency order. Highlights:

| File | Role |
|---|---|
| `00_paths.R` | Output directory resolution |
| `01_io.R` | Data loading helpers |
| `02_validation.R` | Generic input validation |
| `03_alignment.R` | Sample alignment between data and metadata |
| `04_config.R` | `load_config()`, `validate_config()` — central config plumbing |
| `05_export_excel.R` | Excel export for final-results spreadsheets |
| `06_plots.R` | Generic plotting (volcano, MA, heatmaps, profile plots) |
| `07_shiny_contract.R` | **Canonical Shiny payload contract v2.0** — see §8 |
| `08_qc.R` | PCA, sample-distance, density, outlier detection |
| `09_clustering.R` / `09_enrichment.R` | Clustering + generic pathway enrichment (fGSEA / ORA) |
| `10_organism_detection.R`, `11_annotation.R` | Auto-detect organism, multi-organism gene annotation |
| `13_gmt_utils.R` | GMT pathway file utilities |
| `15_user_summary.R`, `16_pptx_helpers.R`, `17_cutoff_panel.R` | Reporting helpers |
| `de_summary_counts.R` | Generic DE-summary counters |

### `R/services/` — external integrations

| File | Role |
|---|---|
| `12_commentary.R` | AI figure-commentary backends (`claude-code` CLI / Anthropic API / OpenAI). Optional; falls back to data-driven commentary if backend unavailable. |

### `R/domain/<omics>/` — omics-specific logic

Four subfolders, one per omics mode: `rnaseq/`, `proteomics/`, `metabolomics/`, `multiomics/`.

Within each, numeric prefixes mirror the analysis flow. Common pattern across modes:

| Prefix | Typical content |
|---|---|
| `00_inputs.R` | Load mode-specific inputs from config |
| `01_*` | Annotation / expression / normalization |
| `02_*` | Filtering |
| `03_*` | Preprocessing / imputation / differential expression |
| `04_*` | Batch correction (rnaseq), feature selection, integration methods (multiomics) |
| `05_*` | Outputs (legacy TSV writers), deconvolution, DE summaries |
| `06_*` | Reporting helpers / enrichment / concordance |
| `07_*` | Pathway, PPI networks, advanced stats, Shiny export |
| `08_*` | Reports |
| `09_*` | Executive summaries |
| `10_*` | Pipeline summaries / domain-specific extras (e.g. metabolomics drift correction) |
| `11_*` | PowerPoint export |
| `90_config_validate.R` | Mode-specific config validator (called by `validate_config()`) |
| `report_template*.Rmd` | RMarkdown report templates |

Note: `R/domain/multiomics/` has a `README.md` worth reading first for that mode.

### `R/modules/<omics>/` — `{targets}`-ready wrappers

Files prefixed `mod_*` (e.g. `02_mod_de.R`, `04_mod_clustering.R`). These are thin orchestrators that combine domain functions into something a single `tar_target(...)` call can invoke. **Most pipeline-touching changes belong here, not in `R/domain/`.**

### `R/pipeline/<omics>/` — `{targets}` orchestration

| File | Defines |
|---|---|
| `R/pipeline/rnaseq/00_pipe_rnaseq.R` | `pipe_rnaseq(skip_outputs = FALSE)` |
| `R/pipeline/proteomics/00_pipe_proteomics.R` | `pipe_proteomics(skip_outputs = FALSE)` |
| `R/pipeline/metabolomics/00_pipe_metabolomics.R` | `pipe_metabolomics(chosen_norm, skip_outputs = FALSE)` |
| `R/pipeline/multiomics/00_pipe_multiomics.R` | `pipe_multiomics()` |
| `R/pipeline/metabolomics/templates/` | RMarkdown report templates used by the metabolomics pipeline |

`_targets.R` calls these factories conditionally based on which `modes:` blocks the config contains. When `modes.multiomics` is present, the single-omics pipelines run with `skip_outputs = TRUE` (only core DE / pathway, no QC / reports / exports).

## 4. Pipeline definition — `_targets.R`

~150 lines. Reads the config path from `Sys.getenv("MULTIOMICS_CONFIG", "config.yaml")` at plan-definition time so changing configs invalidates the right targets. Defines the foundation targets:

- `config_file` → tracked as `format = "file"`
- `config` → result of `validate_config(load_config(config_file))`
- `run_dir` → resolved output directory
- `execution_info_files` → execution metadata snapshot

Then conditionally appends each mode's pipeline by reading the raw YAML to detect `modes.rna`, `modes.proteomics`, `modes.metabolomics`, `modes.multiomics`. Multi-omics is only enabled when ≥2 single-omics modes are configured *and* `modes.multiomics` exists.

**Rule (from `CLAUDE.md`):** helpers do not live in `_targets.R` — only target definitions.

## 8. The "Shiny app" — clarification

`CLAUDE.md` warns "never touch the Shiny app." A grep for `shinyApp`, `runApp`, `shinyServer`, `shinyUI` finds **nothing** in this repo, and there is no `app/`, `shiny/`, or `inst/shiny/` directory.

What *is* here:

- `R/core/07_shiny_contract.R` — defines the **canonical Shiny payload contract v2.0** (`init_shiny_payload()`, `assert_shiny_payload_contract()`).
- Per-omics `*_shiny_export.R` files in `R/domain/<omics>/` that produce payloads conforming to the contract.

**Interpretation:** the actual Shiny app lives in a separate repository and consumes payloads this pipeline emits. Changes to the *contract* break the downstream app, so the "do not touch" rule effectively covers `R/core/07_shiny_contract.R` and the `*_shiny_export.R` files. Confirm with the team before changing payload schemas.

### 8.1 `feature_annot` payload convention (shared across all omics)

The canonical key **`feature_annot`** carries each feature's biological annotation / metadata, and is built identically in all three single-omics payloads (`rnaseq`, `proteomics`, `metabolomics`).

**Structure:**

- A `data.frame`.
- **`rownames(feature_annot)` = feature IDs.**
- **Columns = annotation / metadata columns only** — the feature-ID column is dropped from the body (it lives in the rownames).

**Per-omics behavior** (the columns differ only because each pipeline's `pre$row_data` differs — there is no omics-specific logic):

| Omics | rownames | Columns |
|---|---|---|
| `rnaseq` | gene IDs | annotation columns from `pre$row_data`; **currently may be zero columns** (matrix/tximport input carries only the gene ID) |
| `proteomics` | protein IDs | protein annotation columns from `pre$row_data` (e.g. `Protein.Names`, `Genes`, `First.Protein.Description`) |
| `metabolomics` | feature IDs | all feature-metadata columns from `pre$row_data` (e.g. compound name, m/z, RT, HMDB ID, formula) |

**Downstream consumers:** index features via **`rownames(feature_annot)`** — do **not** expect an ID column such as `feature_annot$feature_id` (the ID column is intentionally removed from the body).

**How it is built:** the shared helper **`build_feature_annot()`** (in `R/core/07_shiny_contract.R`) lifts the ID column to rownames and keeps every other column. Because it carries *all* non-ID columns of `pre$row_data`, **any annotation column added upstream in future automatically flows into `feature_annot`** on the next run, with no change needed in the omics builders. An explicit `annot` argument to a builder still overrides this when supplied.

## 9. Repeated patterns and conventions

These hold across the codebase — recognising them saves you from reinventing.

1. **Numeric file prefixes encode source order.** Both across layers (core → services → domain → modules → pipeline) and within each folder (`00_`, `01_`, …). New files must pick a number that does not violate dependencies.
2. **Per-mode parallelism.** Every omics mode has matching subfolders in `domain/`, `modules/`, `pipeline/`. When adding a feature to one mode, check whether the others should mirror it.
3. **Layered wrappers.** Domain functions do the work; module functions (`mod_*`) wrap them in single-`tar_target`-friendly calls; pipeline files (`pipe_*`) wire those into a DAG.
4. **`90_config_validate.R`** appears in every domain — keeps mode-specific config validation co-located with the domain code that consumes the config.
5. **`skip_outputs` toggle.** Every single-omics pipeline factory accepts `skip_outputs`. When the multi-omics mode is active, single-omics outputs are skipped to avoid wasted work.
6. **Naming.** `snake_case` functions; targets are `<verb>_<noun>` and prefixed by mode (`rna_*`, `prot_*`, `met*`/`metab_*`). See `CLAUDE.md` for details.
7. **Roxygen2 docstrings** on every function in `R/`. New functions should follow.
8. **Reports as RMarkdown.** Each mode has a `report_template*.Rmd` in `R/domain/<omics>/` (plus metabolomics templates in `R/pipeline/metabolomics/templates/`).
9. **Excel + TSV outputs.** Final results are emitted as both Excel (for biologists) and TSV (for downstream tools).
10. **AI commentary is optional with silent fallback.** If the configured backend is unavailable, data-driven commentary is used instead — look for `Falling back to data-driven commentary` in run logs to know which path engaged.

## 11. Warnings / pitfalls

These come from `CLAUDE.md`, the `.gitignore`, and observations from the scan — re-stated here for convenience. **`CLAUDE.md` is the source of truth; when in doubt defer to it.**

### Must-not-touch (per `CLAUDE.md`)

- `_targets/` — pipeline cache, gitignored, machine-specific.
- `renv.lock` — only changed via explicit user request.
- `.Renviron`, `.env`, `*.key`, `*.pem` — secrets.
- `.github/CODEOWNERS`, `.github/workflows/` — CI / review rules.
- The Shiny payload contract — see §8.

### Never run without explicit confirmation

- `git push --force`, `git reset --hard main`, interactive rebases of pushed commits.
- `rm -rf` outside the working tree.
- `targets::tar_destroy()`, `renv::clean()`, `renv::deactivate()`.
- `unlink()` of directories.

### Easy mistakes

- **Putting helpers in `_targets.R`.** They belong in `R/` (the right layer for what they do).
- **Skipping numeric prefixes.** Files load in `sort()` order — picking the wrong number breaks dependencies silently.
- **Forgetting to mirror per-mode.** A pattern in `rnaseq/` often needs `proteomics/` and `metabolomics/` counterparts.
- **Editing per-project YAMLs as if they were templates.** Templates live in `config/templates/` (gitted); real configs are gitignored.
- **Running `tar_make()` autonomously.** It may rebuild expensive computations. Wait for the user to ask.
- **`renv::snapshot()` autonomously.** This is a deliberate human decision — it bumps `renv.lock`.
- **Reading raw bio data into chat.** Use `str()` / `dim()` / `colnames()`. See data safety in `CLAUDE.md`.
- **Adding `library()` calls inside functions.** Use `pkg::fn()` instead.
- **Unseeded randomness.** Anything stochastic must take a seed or use `withr::with_seed()`.

### Unclear / worth confirming

- The `metabolomics/` top-level directory currently contains only a `README.md` describing the metabolomics DAG. The actual code lives in `R/domain/metabolomics/` and `R/pipeline/metabolomics/`. It is unclear whether the top-level `metabolomics/` folder is intended to grow into something else or is purely documentation.
- `tests/test_ppi_elah.R` sits at the top of `tests/` (not in `testthat/`). Unclear whether this is an intentional standalone or a stray.
- `scripts/*.R` is gitignored, but `scripts/` itself contains several committed Python files plus `metabolome_overview_report.Rmd` — implying the gitignore covers user scratch R scripts only.
- `Rplots.pdf` is checked in but also `.gitignore`d — likely a historical leftover.
- The relationship between the top-level `utils/` and `R/core/` is not crisp: both hold utility code, but `utils/` contains standalone runnable scripts (KEGG / GMT generation) rather than functions sourced by the pipeline.
